# Platform Next Phase Plan

> 计划日期：2026-05-12
> 适用范围：`platform/` 二开主仓库

## 目标

在当前“已经跑通基础漫画转视频链路”的前提下，暂停大规模新开发，先把后续工作组织成清晰、可执行的阶段计划，方便后面逐步推进。

本计划聚焦三个方向：

1. 工程稳定化
2. 模型与配置平台化
3. 成片质量提升

---

## 阶段 1：工程稳定化

### 目标

把当前偏原型的实现，收敛成一个更稳定、更可维护的二开底座。

### 核心任务

- [ ] 引入数据库迁移机制
- [ ] 收敛 `Job` / `Asset` / `Storyboard` 数据结构
- [ ] 清理直接 `create_all` 的临时做法
- [ ] 统一错误处理与失败状态
- [ ] 增加任务重试与恢复机制
- [ ] 完善 `.env.example` 与环境说明
- [ ] 增加日志、依赖探测、启动诊断信息

### 阶段产出

- 稳定的数据库 schema 演进方式
- 更可靠的任务生命周期
- 更明确的部署与排障路径

---

## 阶段 2：模型与配置平台化

### 目标

为“替换开源模型、接公司 GPU 服务器”打基础，不再把模型能力写死在具体实现里。

### 核心任务

- [ ] 增加模型配置中心
- [ ] 统一模型适配层接口：
  - [ ] OCR
  - [ ] 脚本生成
  - [ ] TTS
  - [ ] 视频生成
- [ ] 支持按环境切换模型提供方
- [ ] 支持在前端查看当前模型配置状态
- [ ] 支持基础参数管理：
  - [ ] language
  - [ ] voice
  - [ ] subtitle
  - [ ] render mode
  - [ ] 分辨率 / fps / scene duration

### 阶段产出

- 模型能力不再耦合在单一路径中
- 后续可以逐步替换为公司自建模型服务
- 平台具备“配置驱动”的雏形

---

## 阶段 3：视频质量提升

### 目标

把当前“能生成视频”的基础能力，逐步提升到“更像成片”的可交付效果。

### 核心任务

- [ ] 优化 `basic` 模式镜头运动
- [ ] 增加转场策略
- [ ] 增加字幕生成与烧录
- [ ] 增加背景音乐混入
- [ ] 增加 scene 节奏控制
- [ ] 增加封面图 / 片头 / 片尾
- [ ] 增加 storyboard 编辑与 scene 调整能力

### 阶段产出

- 更自然的基础成片
- 更可控的镜头节奏
- 更适合内容生产的结果质量

---

## 阶段 4：产品化与运营能力

### 目标

在核心流程稳定后，再补真正的平台产品能力。

### 核心任务

- [ ] 项目筛选与搜索
- [ ] 任务分页与统计
- [ ] 资产筛选与标签化
- [ ] 批量上传章节
- [ ] 多章节系列化生成
- [ ] 用户 / 团队能力
- [ ] 审片与批注流程
- [ ] 操作日志与审计

### 阶段产出

- 更完整的平台使用体验
- 更适合团队协作和内容生产

---

## 实施顺序建议

### 第一优先级

- 工程稳定化
- 模型配置平台化

### 第二优先级

- 视频质量提升

### 第三优先级

- 产品化与运营能力

---

## 暂缓事项

以下内容目前不建议马上投入：

- 协作系统深度开发
- 多租户复杂权限
- 高级运营后台
- 大规模系列管理
- 复杂品牌包装能力

原因：当前更大的收益来自把“模型可替换、流程可稳定运行、成片质量可持续提升”先打牢。

---

## 里程碑建议

### M1：平台底座稳定

- 数据迁移机制就位
- 任务状态和错误模型稳定
- 启动、部署、排障路径清晰

### M2：模型可替换

- 模型配置入口完成
- 关键能力已有统一适配层
- 能逐步接入公司 GPU 模型服务

### M3：成片质量可交付

- 视频节奏更自然
- 有字幕 / 配乐 / 更好的镜头运动
- 结果可用于真实内容实验

### M4：平台化成型

- 支持更完整的项目、任务、资产管理
- 支持多人协作和更长链路内容生产
